## 1. 改造背景与目标

### 1.1 当前架构问题

| 问题                 | 影响                         |
| -------------------- | ---------------------------- |
| 单用户设计           | 无法支持多用户独立数据       |
| Gateway 承载所有流量 | 性能瓶颈，CRUD 与实时混合    |
| 前端直连 WebSocket   | 无法利用 HTTP 缓存，调试困难 |
| 无配额计费           | 无法实现订阅分级             |
| 对话/记忆无持久化    | 用户数据丢失风险             |

### 1.2 改造目标

1. **多租户隔离**: 每个用户数据完全隔离，userId 作为租户标识
2. **职责分离**: Gateway 专注实时控制，App Server 处理 CRUD
3. **数据持久化**: 对话、记忆、文件、配置全部入库
4. **配额计费**: 支持按用量计费的订阅模式
5. **向后兼容**: 改造期间不破坏现有功能

## 2. 数据库多租户隔离方案

### 2.1 隔离策略

采用 **共享数据库 + 行级隔离** 策略：

| 策略         | 优点             | 缺点             | 适用场景      |
| ------------ | ---------------- | ---------------- | ------------- |
| 独立数据库   | 完全隔离         | 成本高、运维复杂 | 大型企业客户  |
| 独立 Schema  | 较好隔离         | 迁移复杂         | 中型 SaaS     |
| **行级隔离** | 成本低、运维简单 | 需代码保证隔离   | 个人用户 SaaS |

### 2.2 租户标识设计

```typescript
// 租户 = 用户，userId 作为租户标识
type TenantId = string; // 等同于 userId

// 所有用户数据表都包含 userId 字段
interface TenantScopedEntity {
  userId: string; // 租户标识，必填
  // ... 其他字段
}
```

### 2.3 TenantScopedRepository 基类

```typescript
// src/db/repositories/tenant-scope.ts

/**
 * 多租户 Repository 基类
 *
 * 所有用户数据 Repository 继承此类，自动实现 userId 隔离
 */
export class TenantScopedRepository {
  constructor(
    protected readonly db: Database,
    protected readonly userId: string,
  ) {
    if (!userId) {
      throw new Error("[TenantScopedRepository] userId is required");
    }
  }

  get tenantId(): string {
    return this.userId;
  }

  /**
   * 构建带租户过滤的查询条件
   */
  protected withTenantFilter<T extends { userId: string }>(
    table: T,
    additionalConditions?: SQL,
  ): SQL {
    const tenantCondition = eq(table.userId, this.userId);
    return additionalConditions ? and(tenantCondition, additionalConditions) : tenantCondition;
  }
}
```

### 2.4 数据表分类

| 分类       | 表名                                                                                                         | 隔离方式        |
| ---------- | ------------------------------------------------------------------------------------------------------------ | --------------- |
| 用户数据表 | conversations, messages, user_memories, user_files, user_custom_skills, user_assistant_configs, usage_quotas | userId 行级隔离 |
| 全局配置表 | subscription_plans, skill_categories, system_configs                                                         | 无需隔离        |
| 管理员表   | admins, admin_sessions, admin_audit_logs                                                                     | 独立体系        |
| 用户基础表 | users, user_sessions, subscriptions                                                                          | 按 id 查询      |

## 5. Agent 多租户改造方案

### 5.1 Session Key 改造

```typescript
// 改造前：无用户维度
type SessionKey = `${channelType}:${channelId}:${senderId}`;

// 改造后：增加用户维度
type SessionKey = `${userId}:${channelType}:${channelId}:${senderId}`;

// 向后兼容：无 userId 前缀视为 "default" 用户
function parseSessionKey(key: string): SessionKeyParts {
  const parts = key.split(":");
  if (parts.length === 3) {
    // 旧格式，兼容处理
    return { userId: "default", channelType: parts[0], channelId: parts[1], senderId: parts[2] };
  }
  return { userId: parts[0], channelType: parts[1], channelId: parts[2], senderId: parts[3] };
}
```

### 5.3 工具权限校验

```typescript
// src/agents/tool-guard.ts

/**
 * 工具调用权限守卫
 *
 * 校验用户是否有权限操作目标设备
 */
async function checkToolPermission(
  userId: string,
  toolName: string,
  params: Record<string, unknown>,
): Promise<{ allowed: boolean; reason?: string }> {
  // 需要设备权限的工具
  const deviceTools = ["exec", "process", "file_read", "file_write", "system_info"];

  if (!deviceTools.includes(toolName)) {
    return { allowed: true };
  }

  const deviceId = params.deviceId as string;
  if (!deviceId) {
    return { allowed: false, reason: "Missing deviceId" };
  }

  const device = await deviceRepo.findById(deviceId);
  if (!device || device.userId !== userId) {
    return { allowed: false, reason: "Device not owned by user" };
  }

  return { allowed: true };
}
```

### 7.2 共享 API 客户端

```typescript
// packages/api-client/src/client.ts

export class ApiClient {
  private baseUrl: string;
  private tokenProvider: TokenProvider;

  async get<T>(path: string): Promise<ApiResponse<T>> {
    return this.request<T>("GET", path);
  }

  async post<T>(path: string, body?: unknown): Promise<ApiResponse<T>> {
    return this.request<T>("POST", path, body);
  }

  private async request<T>(method: string, path: string, body?: unknown): Promise<ApiResponse<T>> {
    const token = await this.tokenProvider.getAccessToken();

    const response = await fetch(`${this.baseUrl}${path}`, {
      method,
      headers: {
        "Content-Type": "application/json",
        ...(token && { Authorization: `Bearer ${token}` }),
      },
      body: body ? JSON.stringify(body) : undefined,
    });

    // 401 时自动刷新 Token
    if (response.status === 401) {
      const refreshed = await this.tokenProvider.refreshToken();
      if (refreshed) {
        return this.request<T>(method, path, body);
      }
      this.tokenProvider.onAuthExpired?.();
      throw new AuthExpiredError("Session expired");
    }

    return response.json();
  }
}
```

### 7.3 各应用迁移策略

| 应用           | CRUD 操作      | 实时操作       |
| -------------- | -------------- | -------------- |
| admin-console  | 100% HTTP REST | 无需 WebSocket |
| web-admin      | HTTP REST      | 保留 WebSocket |
| Windows 客户端 | HTTP REST      | 保留 WebSocket |
