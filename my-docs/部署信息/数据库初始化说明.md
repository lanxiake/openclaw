## 自动初始化

### PostgreSQL 容器初始化

PostgreSQL 容器在首次启动时会自动执行 `/docker-entrypoint-initdb.d/` 目录下的 SQL 脚本。

### 初始化脚本位置

初始化脚本位于：`docker-init/postgres/01-init.sql`

### 初始化内容

当前初始化脚本包含：

1. **启用 UUID 扩展**

   ```sql
   CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
   ```

2. **启用 pg_trgm 扩展**（用于模糊搜索）

   ```sql
   CREATE EXTENSION IF NOT EXISTS pg_trgm;
   ```

3. **启用 btree_gin 扩展**（用于复合索引）
   ```sql
   CREATE EXTENSION IF NOT EXISTS btree_gin;
   ```

### 挂载初始化脚本

在 `docker-compose.infra.yml` 中，初始化脚本通过 volume 挂载：

```yaml
volumes:
  - postgres-data:/var/lib/postgresql/data
  - ./docker-init/postgres:/docker-entrypoint-initdb.d
```

**注意**: 初始化脚本只在数据库首次创建时执行。如果数据库已存在，脚本不会再次执行。

## 手动初始化

### 在已有数据库上执行初始化

如果需要在已有数据库上执行初始化脚本：

```bash
# 方法 1: 使用 docker-compose exec
docker-compose -f docker-compose.infra.yml exec postgres psql -U openclaw_admin -d openclaw_prod -f /docker-entrypoint-initdb.d/01-init.sql

# 方法 2: 直接连接数据库
docker-compose -f docker-compose.infra.yml exec postgres psql -U openclaw_admin -d openclaw_prod

# 在 psql 中执行
\i /docker-entrypoint-initdb.d/01-init.sql
```

### 检查扩展是否已安装

```bash
docker-compose -f docker-compose.infra.yml exec postgres psql -U openclaw_admin -d openclaw_prod -c "\dx"
```

应该看到以下扩展：

- `uuid-ossp`
- `pg_trgm`
- `btree_gin`

## 数据库迁移

### 使用 Drizzle ORM 迁移

OpenClaw 使用 Drizzle ORM 进行数据库 schema 管理。

#### 生成迁移文件

在开发环境中，修改 schema 后生成迁移：

```bash
# 设置数据库连接
export DATABASE_URL="postgresql://openclaw_admin:password@localhost:22001/openclaw_prod"

# 生成迁移文件
pnpm db:generate
```

迁移文件会生成在 `src/db/migrations/` 目录。

#### 执行迁移

在生产环境中执行迁移：

```bash
# 设置数据库连接
export DATABASE_URL="postgresql://openclaw_admin:password@localhost:22001/openclaw_prod"

# 执行迁移
pnpm db:migrate
```

**重要提示**:

- 执行迁移前请务必备份数据库
- 建议先在测试环境验证迁移
- 生产环境迁移建议在低峰期执行

#### 查看迁移状态

```bash
# 连接到数据库
docker-compose -f docker-compose.infra.yml exec postgres psql -U openclaw_admin -d openclaw_prod

# 查看迁移表
SELECT * FROM drizzle.__drizzle_migrations;
```

### 迁移脚本位置

迁移脚本位于：`src/db/migrations/`

当前迁移文件：

- `0000_wandering_the_spike.sql` - 初始数据库 schema

## 初始数据

### 创建管理员账户

使用脚本创建初始管理员账户：

```bash
# 设置数据库连接
export DATABASE_URL="postgresql://openclaw_admin:password@localhost:22001/openclaw_prod"

# 创建管理员
pnpm create-admin
```

脚本会提示输入：

- 用户名
- 邮箱
- 密码

### 初始化种子数据（可选）

如果需要初始化测试数据：

```bash
# 设置数据库连接
export DATABASE_URL="postgresql://openclaw_admin:password@localhost:22001/openclaw_prod"

# 运行种子脚本
pnpm seed-dev
```

**注意**: 种子脚本仅用于开发环境，生产环境不建议使用。

## 常见问题

### 1. 初始化脚本未执行

**问题**: PostgreSQL 容器启动后，初始化脚本未执行。

**原因**:

- 数据库数据卷已存在（非首次启动）
- 初始化脚本路径不正确

**解决方案**:

- 删除数据卷重新创建（**会丢失所有数据**）:
  ```bash
  docker-compose -f docker-compose.infra.yml down -v
  docker-compose -f docker-compose.infra.yml up -d postgres
  ```
- 或手动执行初始化脚本（见[手动初始化](#手动初始化)）

### 2. 扩展安装失败

**问题**: 执行 `CREATE EXTENSION` 时报错。

**原因**:

- PostgreSQL 版本不支持该扩展
- 缺少必要的系统包

**解决方案**:

- 检查 PostgreSQL 版本（需要 12+）
- 确保使用官方 PostgreSQL 镜像

### 3. 迁移执行失败

**问题**: 执行 `pnpm db:migrate` 时报错。

**可能原因**:

- 数据库连接失败
- 迁移文件语法错误
- 数据库已有冲突的 schema

**解决方案**:

- 检查 `DATABASE_URL` 环境变量
- 查看错误日志，定位具体问题
- 如有冲突，手动修复或回滚

### 4. 权限问题

**问题**: 执行 SQL 时提示权限不足。

**解决方案**:

- 确保使用正确的数据库用户（`openclaw_admin`）
- 检查用户权限：
  ```sql
  \du openclaw_admin
  ```

## 备份与恢复

### 备份数据库

```bash
# 创建备份
docker-compose -f docker-compose.infra.yml exec postgres pg_dump -U openclaw_admin openclaw_prod > backup_$(date +%Y%m%d_%H%M%S).sql

# 压缩备份
gzip backup_*.sql
```

### 恢复数据库

```bash
# 解压备份
gunzip backup_20260101_120000.sql.gz

# 恢复备份
docker-compose -f docker-compose.infra.yml exec -T postgres psql -U openclaw_admin openclaw_prod < backup_20260101_120000.sql
```
