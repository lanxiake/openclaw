## 3. 数据库层实现

### 3.1 Schema 定义

**文件**: `src/db/schema/memories.ts`

```typescript
// user_memories 表结构
{
  id: uuid (PK)
  userId: uuid (FK → users.id)  // 多租户隔离核心
  type: enum ['episodic', 'profile', 'preference', 'fact']
  category: text  // work, personal, skill
  content: text   // 记忆文本内容
  embedding: vector(1536)  // pgvector 向量字段
  importance: integer (1-10)  // 重要性权重
  sourceType: enum ['conversation', 'file', 'manual', 'system']
  sourceId: text  // 关联的 conversationId/fileId
  metadata: jsonb  // 扩展数据
  isActive: boolean  // 逻辑删除标记
  createdAt: timestamp
  updatedAt: timestamp
}
```

### 3.2 索引设计

| 索引                | 字段              | 用途           |
| ------------------- | ----------------- | -------------- |
| `user_id_idx`       | userId            | 租户隔离查询   |
| `user_type_idx`     | userId + type     | 按类型过滤     |
| `user_category_idx` | userId + category | 按分类过滤     |
| `importance_idx`    | importance        | 重要性排序     |
| `embedding_idx`     | embedding (HNSW)  | 向量相似度搜索 |

## 4. 与扩展的关系

### 4.1 memory-core 扩展

**位置**: `extensions/memory-core/`

**职责**:

- 注册 `memory_search` 工具 - 搜索记忆
- 注册 `memory_get` 工具 - 获取单条记忆
- 注册 `memory` CLI 命令组

**依赖关系**:

```
extensions/memory-core/
    ↓ 调用
src/memory/manager.ts
    ↓ 使用
src/db/repositories/memories.ts
    ↓ 访问
PostgreSQL user_memories 表
```

**结论**: memory-core 是记忆系统的用户入口，**必须保留**。

### 4.2 memory-lancedb 扩展

**位置**: `extensions/memory-lancedb/`

**职责**:

- 提供 LanceDB 向量数据库后端
- 实现自动回忆（auto-recall）
- 实现自动捕获（auto-capture）
- 注册 lifecycle hooks

**依赖关系**:

```
extensions/memory-lancedb/
    ↓ 独立实现
LanceDB 向量数据库
    ↓ 使用
OpenAI Embeddings API
```

**与 src/memory 的关系**:

- **互补而非竞争**
- memory-core 使用 PostgreSQL + pgvector
- memory-lancedb 使用 LanceDB（可选增强）

**结论**: memory-lancedb 是可选的生产环境增强，建议保留但非必须。

## 5. 与架构设计文档对比

### 5.1 设计文档预期

**来源**: `my-docs/架构改造文档-v2/03-记忆与存储系统设计.md`

| 层级 | 名称     | 存储方案          | 用途           |
| ---- | -------- | ----------------- | -------------- |
| L1   | 工作记忆 | Redis/内存        | 当前会话上下文 |
| L2   | 情景记忆 | PostgreSQL + 向量 | 对话历史、事件 |
| L3   | 档案记忆 | PostgreSQL        | 用户画像、偏好 |
| L4   | 知识记忆 | Neo4j 图数据库    | 知识图谱       |

### 5.2 实际实现状态

| 层级        | 状态    | 实现情况                                      |
| ----------- | ------- | --------------------------------------------- |
| L1 工作记忆 | ⚠️ 部分 | 仅在 memory-lancedb 的 lifecycle hooks 中使用 |
| L2 情景记忆 | ✅ 完成 | user_memories 表 + pgvector 完整实现          |
| L3 档案记忆 | ⚠️ 部分 | 使用 users 表存储，缺乏专用 profile 表        |
| L4 知识记忆 | ❌ 缺失 | 未实现，未列入当前优先级                      |

### 5.3 差距分析

#### L1 工作记忆

**设计预期**:

- Redis 存储当前会话上下文
- 快速读写，自动过期

**实际情况**:

- 无独立的 L1 实现
- 会话上下文在 Agent 运行时内存中管理
- memory-lancedb 的 hooks 提供部分能力

**建议**:

- 如需独立 L1，可在 `src/infrastructure/redis/` 中实现
- 当前实现可满足基本需求

#### L3 档案记忆

**设计预期**:

- 专用表存储用户画像
- 包含：性别、年龄、兴趣、偏好、习惯等

**实际情况**:

- 使用 users 表的 metadata 字段
- 缺乏结构化的 profile schema

**建议**:

- 创建 `user_profiles` 表
- 或扩展 users 表增加 profile 相关字段

#### L4 知识记忆

**设计预期**:

- Neo4j 图数据库
- 存储实体关系、知识图谱

**实际情况**:

- 完全未实现
- 未列入当前开发优先级

**建议**:

- 作为后续增强功能
- 可作为独立扩展实现

## 6. 多租户实现验证

### 6.1 数据隔离

✅ **已实现**:

- `user_memories` 表包含 `userId` 字段
- `MemoryRepository` 继承 `TenantScopedRepository`
- 所有查询自动注入 `userId` 条件

### 6.2 代码示例

```typescript
// src/db/repositories/memories.ts
class MemoryRepository extends TenantScopedRepository {
  async findAll(userId: string, filters?: MemoryFilters) {
    return this.db
      .select()
      .from(userMemories)
      .where(
        and(
          eq(userMemories.userId, userId), // 租户隔离
          filters?.type ? eq(userMemories.type, filters.type) : undefined,
          filters?.activeOnly ? eq(userMemories.isActive, true) : undefined,
        ),
      );
  }
}
```

### 6.3 验证结论

| 检查项                                 | 状态 |
| -------------------------------------- | ---- |
| Schema 包含 userId                     | ✅   |
| Repository 继承 TenantScopedRepository | ✅   |
| 查询自动注入 userId                    | ✅   |
| 索引支持 userId 查询                   | ✅   |

**结论**: 记忆系统多租户改造已完成。

1. **创建 user_profiles 表**
   - 存储 L3 档案记忆
   - 包含结构化的用户画像字段

2. **完善 pgvector 索引**
   - 确保 HNSW 索引已创建
   - 优化向量搜索性能

### 7.2 中期改进（P2）

1. **实现 Redis 工作记忆**
   - 在 `src/infrastructure/redis/` 中实现
   - 支持会话级别的快速缓存

2. **评估 memory-lancedb 生产部署**
   - 测试自动回忆/捕获功能
   - 评估与 PostgreSQL 方案的性能对比

### 7.3 长期改进（P3）

1. **知识图谱实现**
   - 评估 Neo4j vs PostgreSQL JSON 方案
   - 作为独立扩展实现
