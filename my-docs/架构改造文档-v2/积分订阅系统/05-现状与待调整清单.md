# 积分订阅系统 — 现状与待调整清单

> 最后更新：2026-02-25

## 1. 总体现状

积分订阅系统的大部分核心功能已实现，包括：

- 积分账户、批次、流水的完整数据库 Schema
- FIFO 积分消费机制
- 模型定价和成本计算
- 订阅管理（创建/更新/取消/续费）
- 支付订单生命周期管理
- Admin Console 管理页面（积分/订阅/订单）
- Windows 客户端积分视图
- Gateway WebSocket RPC 和 REST API 接口

## 3. 需要新增的功能

### 3.1 免费用户积分上限

**需求**：免费用户积分持有上限 3000

**当前**：无限制

**实现方案**：

- 在 `grantRegistrationBonus()` 和 `grantInviteReward()` 中增加上限检查
- 新增 `FREE_USER_CREDIT_CAP = 3000` 常量
- 发放前检查：当前余额 + 待发放积分 ≤ 上限

### 3.2 首月优惠

**需求**：月付首月 3 元

**当前**：`subscriptions` 表有 `isFirstMonth` 字段，但支付流程未使用

**实现方案**：

- 创建月付订阅时设置 `isFirstMonth = true`
- 创建订单时检查 `isFirstMonth`，价格设为 300 分
- 续费时自动将 `isFirstMonth` 更新为 `false`

### 3.3 积分包配置和管理

**需求**：Admin Console 可管理积分包定价、积分数量、推荐标记，查看购买统计

**当前**：积分包定义未在代码中配置

**实现方案**：

- 在 `system_configs` 表中存储积分包配置
- 新增管理员 API 端点（CRUD + 统计）
- Admin Console CreditsPage 增加积分包管理区域

### 3.4 用户端积分包列表 API

**需求**：用户端获取可购买的积分包列表

**当前**：未实现

**实现方案**：

- 新增 `GET /api/credits/packs` 端点
- 从 `system_configs` 读取积分包配置
- 返回激活的积分包列表（按 sortOrder 排序）

### 3.5 订阅修改权限控制

**需求**：仅管理员可修改和取消订阅

**当前**：用户端有取消订阅功能

**实现方案**：

- 移除或禁用用户端的订阅取消 API
- 保留管理员 API 的取消/修改功能
- Gateway RPC 中 `assistant.payment` 相关方法去掉取消/修改订阅能力

### 3.6 订阅服务数据库迁移

**需求**：订阅数据存储在 PostgreSQL

**当前**：`src/assistant/subscription/service.ts` 使用文件系统（JSON 文件）存储

**说明**：数据库 Schema（`subscriptions` 表）已就绪，Repository 层已实现。但 `service.ts` 仍在使用文件存储。需要将 service.ts 的数据操作迁移到使用 `SubscriptionRepository`。

### 3.7 模型提供商自动获取

**需求**：PricingPage 自动获取已录入的模型提供商

**当前**：手动输入模型 ID

**实现方案**：

- 从系统配置或模型注册表获取已配置的提供商列表
- PricingPage 加载时获取提供商和模型列表
- 下拉选择替代手动输入
