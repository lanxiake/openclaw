# 配置系统与认证体系

> 文档版本：v1.0 | 更新日期：2026-02-22
>
> 本文档详细分析 OpenClaw 的多源配置系统和三层认证体系。

---

## 1. 配置系统架构

### 1.1 配置源优先级

```
 优先级高                                           优先级低
┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
│ 数据库配置 │ > │ 文件配置  │ > │ 环境变量  │ > │  默认值   │
└──────────┘  └──────────┘  └──────────┘  └──────────┘
  5 张表        YAML/JSON5    ${VAR}        defaults.ts
```

**数据库配置表**:

| 表名                                   | 用途                                           |
| -------------------------------------- | ---------------------------------------------- |
| `gateway_configs`                      | 网关运行参数                                   |
| `model_providers`                      | AI 模型提供商（API Key / Base URL / 模型列表） |
| `agent_configs`                        | Agent 默认配置                                 |
| `system_configs`                       | 系统 KV 键值配置                               |
| `auth_profiles` + `auth_profile_order` | 认证配置文件及轮转顺序                         |

### 1.2 配置文件目录

```
src/config/
├── config.ts                 主导出（re-export 所有）
├── io.ts                     文件 I/O、JSON5 解析、备份
├── types.ts                  联合导出所有类型
├── types.base.ts             基础类型 (ReplyMode / DmScope)
├── types.agents.ts           Agent 配置
├── types.channels.ts         频道配置 (telegram / discord ...)
├── types.models.ts           模型定义、成本、上下文窗口
├── types.auth.ts             OAuth / API Key / 轮换策略
├── types.hooks.ts            Hook 配置
├── types.plugins.ts          插件配置
├── types.openclaw.ts         根配置（聚合所有）
├── defaults.ts               默认值应用
├── env-vars.ts               环境变量收集
├── env-substitution.ts       ${VAR} 替换
├── includes.ts               配置文件 include
├── merge-config.ts           配置合并
├── normalize-paths.ts        路径规范化
├── validation.ts             Zod schema 验证
└── zod-schema.ts             完整验证 schema
```

### 1.3 配置文件格式示例

```yaml
# ~/.openclaw/config.yaml

identity:
  name: "Claude"

agents:
  list:
    - id: "main"
      model: "anthropic/claude-opus-4-5"
      apiTimeout: 120000

bindings:
  - agentId: "main"
    match:
      channel: "telegram"
      accountId: "*" # 通配符

  - agentId: "support"
    match:
      channel: "discord"
      guildId: "12345"

telegram:
  accounts:
    - name: "default"
      token: "${TELEGRAM_BOT_TOKEN}"

session:
  dmScope: "per-channel-peer"
  identityLinks:
    "alice":
      - "telegram:12345"
      - "discord:alice#9999"

hooks:
  internal:
    enabled: true
    config:
      "boot-md":
        enabled: true

plugins:
  include:
    - "/path/to/plugin"
  enabled:
    - "plugin-id"
```

### 1.4 配置加载流程

```
loadConfig()
│
├─ ① 解析文件位置
│     ~/.openclaw/config.yaml 或 --config 参数
│
├─ ② 读取 YAML/JSON5 文件
│     normalizeConfigPaths()
│
├─ ③ 处理 includes
│     递归合并外部配置文件
│
├─ ④ 环境变量替换
│     ${TELEGRAM_BOT_TOKEN} → 实际值
│
├─ ⑤ 运行时覆盖
│     CLI --set 参数
│
├─ ⑥ 应用默认值
│     applyAgentDefaults()
│     applySessionDefaults()
│     applyMessageDefaults()
│     applyModelDefaults()
│
├─ ⑦ Zod Schema 验证
│     OpenClawSchema.parse()
│
├─ ⑧ 插件配置验证
│     validateConfigObjectWithPlugins()
│
└─ ✅ 返回 OpenClawConfig
```

### 1.5 数据库配置加载

**文件**: `src/gateway/config-loader.ts`

```typescript
// 从数据库加载所有配置
loadAllDatabaseConfigs() → DatabaseConfigs | null

// 确保记忆系统默认配置存在
ensureMemorySystemConfigs(db: Database) → void
```

**DatabaseConfigs 结构**:

```typescript
interface DatabaseConfigs {
  gatewayConfig: DbGatewayConfig | null;
  modelProviders: ModelProvider[];
  agentConfig: AgentDefaultConfig | null;
  systemConfigs: Record<string, unknown>;
  authProfiles: AuthProfile[];
  authProfileOrders: AuthProfileOrderRecord[];
}
```

### 1.6 配置合并逻辑

**文件**: `src/gateway/config-merger.ts`

```typescript
mergeFileAndDbConfigs(fileConfig, dbConfigs) → OpenClawConfig
```

**合并策略**（遵循不可变模式）:

| 配置项          | 合并方式                              |
| --------------- | ------------------------------------- |
| Gateway 配置    | 深度合并（DB 覆盖文件）               |
| Model Providers | 按 `providerKey` 合并（DB 补充/覆盖） |
| Agent 配置      | 深度合并                              |
| System 配置     | KV 覆盖                               |
| Auth Profiles   | 深度合并（DB 优先）                   |

### 1.7 热重载机制

**文件**: `src/gateway/config-db-watcher.ts`

```
PostgreSQL LISTEN/NOTIFY
│
├─ 监听表: gateway_configs, model_providers, agent_configs,
│          auth_profiles, system_configs
│
├─ 变更回调:
│   ├─ action === "hot"      → 动态应用配置（无中断）
│   └─ action === "restart"  → 网关重启
│
└─ 支持无停机配置更新
```

## 2. 三层认证体系

### 2.1 总览

```
┌──────────────────────────────────────────────────────┐
│                    第一层：Gateway 认证                │
│  Token / 密码 / Tailscale / 设备令牌                  │
│  → 决定客户端能否连接网关                              │
├──────────────────────────────────────────────────────┤
│                 第二层：Auth Profiles                  │
│  API Key / OAuth / Token（三级优先）                   │
│  → 决定使用哪个凭据调用 AI 模型                        │
├──────────────────────────────────────────────────────┤
│                   第三层：频道认证                      │
│  每个频道插件的 ChannelAuthAdapter                     │
│  → 决定如何与外部平台通信                              │
└──────────────────────────────────────────────────────┘
```

### 2.2 第一层：Gateway 认证

**文件**: `src/gateway/auth.ts` (200+ 行)

```typescript
// 认证模式
type ResolvedGatewayAuthMode = "token" | "password" | "none";

// 认证配置
type ResolvedGatewayAuth = {
  mode: ResolvedGatewayAuthMode;
  token?: string;
  password?: string;
  allowTailscale: boolean;
};

// 认证结果
type GatewayAuthResult = {
  ok: boolean;
  method?: "token" | "password" | "tailscale" | "device-token";
  user?: string;
  reason?: string;
};
```

**验证流程**:

```
客户端发送凭据
│
├─ ① Token 验证（常时间比较，防时序攻击）
├─ ② 密码验证
├─ ③ Tailscale 身份验证
└─ ④ 设备令牌验证
```

**辅助函数**:

```typescript
// 检测是否为本地直连（可跳过认证）
isLocalDirectRequest(req?, trustedProxies?) → boolean

// 解析认证配置
resolveGatewayAuth(params) → ResolvedGatewayAuth
```

### 2.3 第二层：Auth Profiles（模型认证）

#### 2.3.1 凭据类型

**文件**: `src/agents/auth-profiles/types.ts` (74 行)

```typescript
// 三种凭据类型（互斥）
type ApiKeyCredential = { type: "api_key"; key: string; email?: string };
type TokenCredential = { type: "token"; token: string; expires?: number };
type OAuthCredential = { type: "oauth"; access: string; refresh?: string };

// Profile 失败原因（影响冷却期）
type AuthProfileFailureReason =
  | "auth" // 401 - 认证失败
  | "rate_limit" // 429 - 速率限制
  | "billing" // 402 - 账单问题
  | "timeout" // 408 - 超时
  | "format" // 400 - 格式错误
  | "unknown";

// 使用统计
type ProfileUsageStats = {
  lastUsed?: number;
  cooldownUntil?: number;
  disabledUntil?: number;
  disabledReason?: AuthProfileFailureReason;
  errorCount?: number;
  failureCounts?: Record<AuthProfileFailureReason, number>;
};

// 完整 Auth Store
type AuthProfileStore = {
  version: number;
  profiles: Record<string, AuthProfileCredential>;
  order?: Record<string, string[]>; // per-provider 轮转顺序
  lastGood?: Record<string, string>; // 上次成功的 profile
  usageStats?: Record<string, ProfileUsageStats>;
};
```

#### 2.3.2 三级优先级

```
 优先级高                                        优先级低
┌───────────┐  ┌───────────┐  ┌─────────────┐
│ 租户级 DB  │ > │ 系统级 DB  │ > │ 文件级 JSON  │
│ (per-user) │  │ (global)  │  │ (~/.openclaw)│
└───────────┘  └───────────┘  └─────────────┘
```

**文件**: `src/agents/auth-profiles/db-store.ts` (226 行)

```typescript
// 从数据库加载
loadDbAuthProfileStore(userId?) → AuthProfileStore | null

// 转换 DB 记录
convertDbProfilesToAuthStore(dbProfiles, dbOrders) → AuthProfileStore

// 合并文件 store 和 DB store（DB 优先覆盖）
mergeAuthStores(fileStore, dbStore) → AuthProfileStore
```

#### 2.3.3 Profile 轮转与冷却

**文件**: `src/agents/auth-profiles/usage.ts` (150+ 行)

```typescript
// 检查冷却状态
isProfileInCooldown(store, profileId) → boolean

// 冷却时间计算（指数退避）
calculateAuthProfileCooldownMs(errorCount) → number
  // min(60分钟, 60秒 × 5^(errorCount-1))

// 标记成功
markAuthProfileUsed({ store, profileId, agentDir }) → void

// 标记失败（触发冷却期）
markAuthProfileFailure({ store, profileId, reason, cfg, agentDir }) → void
```

#### 2.3.4 Model Auth 解析

**文件**: `src/agents/model-auth.ts` (392 行)

```typescript
// 解析 provider 认证
getApiKeyForModel(params) → ResolvedProviderAuth

type ResolvedProviderAuth = {
  apiKey?: string
  profileId?: string
  source: string
  mode: "api-key" | "oauth" | "token" | "aws-sdk"
}

// Profile 轮转顺序
resolveAuthProfileOrder({ cfg, store, provider, preferredProfile }) → string[]
```

**认证源优先级**:

```
① 指定的 profile ID（用户锁定）
│
├─ ② Config 中 AWS SDK 配置 (for Bedrock)
│
├─ ③ Auth Profile 轮转顺序
│     按 store.order + usageStats 排序
│     跳过冷却中的 profile
│
├─ ④ 环境变量
│     OPENAI_API_KEY
│     ANTHROPIC_API_KEY
│     GOOGLE_API_KEY
│     ...
│
├─ ⑤ 自定义 Provider 配置
│     cfg.models.providers[provider].apiKey
│
└─ ⑥ AWS SDK 默认链（Bedrock）
```

### 2.4 第三层：频道认证

每个频道插件通过 `ChannelAuthAdapter` 实现自己的认证逻辑：

| 频道     | 认证方式             |
| -------- | -------------------- |
| Telegram | Bot Token            |
| Discord  | Bot Token + OAuth    |
| Slack    | Socket Mode Token    |
| WhatsApp | 多账户认证           |
| Signal   | 本地 CLI 凭据        |
| iMessage | BlueBubbles 桥接认证 |
