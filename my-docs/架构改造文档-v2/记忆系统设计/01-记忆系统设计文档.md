## 1. 概述

### 1.1 背景

OpenClaw AI 个人助理需要具备"记忆"能力，以提供个性化、连贯的服务体验。本文档定义精简的记忆系统架构，聚焦**多租户记忆隔离**和**日常使用**两个核心目标。

### 1.2 设计原则

1. **简单优先**: 优先满足日常使用，高级功能通过扩展接口预留
2. **多租户隔离**: 所有记忆数据按 userId 严格隔离
3. **可插拔架构**: 统一接口，支持多种后端实现
4. **渐进式扩展**: 知识图谱、GraphRAG、对象存储等在扩展接口就绪后按需实现

### 1.3 设计目标

| 目标       | 描述                                |
| ---------- | ----------------------------------- |
| 个性化服务 | 记住用户偏好、习惯，提供定制化响应  |
| 上下文连贯 | 跨会话保持对话连贯性                |
| 知识积累   | 学习用户领域知识，提升专业能力      |
| 隐私保护   | 用户数据加密存储，支持选择性遗忘    |
| 可插拔架构 | 统一接口，支持多种后端实现          |
| 独立部署   | 可嵌入 OpenClaw，也可独立服务化部署 |

### 1.4 术语定义

| 术语                             | 定义                                     |
| -------------------------------- | ---------------------------------------- |
| **情节记忆 (Episodic Memory)**   | 长期对话历史，包含摘要、关键事件、时间线 |
| **画像记忆 (Profile Memory)**    | 用户事实、偏好、行为模式的持久化存储     |
| **知识记忆 (Knowledge Memory)**  | 文档管理与向量索引，支持语义检索         |
| **记忆提供者 (Memory Provider)** | 实现记忆接口的具体后端实现               |
| **记忆上下文 (Memory Context)**  | 聚合多层记忆的用户完整上下文             |

### 2.2 层级总览

| 层级 | 名称     | 存储周期 | 数据类型             | 推荐后端            | 轻量后端            |
| ---- | -------- | -------- | -------------------- | ------------------- | ------------------- |
| L1   | 情节记忆 | 长期     | 对话历史、事件时间线 | PostgreSQL+pgvector | 内存 Map            |
| L2   | 画像记忆 | 永久     | 用户档案、偏好设置   | PostgreSQL          | 内存 Map            |
| L3   | 知识记忆 | 永久     | 文档、向量索引       | PostgreSQL+pgvector | SQLite + sqlite-vec |

### 2.3 已移除/推迟的模块

| 模块       | 状态 | 说明                                       |
| ---------- | ---- | ------------------------------------------ |
| 工作记忆   | 移除 | Agent 运行时自行管理会话上下文             |
| 对象存储   | 推迟 | 多媒体存储作为独立模块后续实现             |
| 情绪追踪   | 推迟 | 从情节记忆中移除，类型定义已标记 @future   |
| 知识图谱   | 推迟 | Entity/Relationship 类型保留但标记 @future |
| GraphRAG   | 推迟 | Community/answerWithGraph 类型保留         |
| 对话转知识 | 推迟 | importConversation 方法移除                |

### 3.3 现有系统问题

| 组件         | 现状                           | 问题                     |
| ------------ | ------------------------------ | ------------------------ |
| **会话存储** | JSON5 文件 + JSONL 记录        | 无结构化查询、无用户隔离 |
| **记忆索引** | SQLite + sqlite-vec            | 单机限制、无分布式支持   |
| **嵌入模型** | OpenAI/Gemini/本地             | 无统一管理接口           |
| **搜索方式** | 混合搜索 (0.7 向量 + 0.3 BM25) | 功能有限                 |
| **媒体存储** | 文件系统 + 2 分钟 TTL          | 不持久、无对象存储       |

## 4. 功能需求

### 4.1 L1 情节记忆

**目的**: 存储长期对话历史、关键事件

**功能点**:

| ID    | 功能     | 说明                     |
| ----- | -------- | ------------------------ |
| EM-01 | 存储对话 | 保存完整对话到历史       |
| EM-02 | 生成摘要 | AI 自动生成对话摘要      |
| EM-03 | 提取主题 | 识别对话主要话题         |
| EM-04 | 记录决定 | 提取对话中做出的决定     |
| EM-05 | 事件检测 | 自动检测和分类关键事件   |
| EM-06 | 事件评分 | 计算事件重要性分数 (0-1) |
| EM-07 | 时间线   | 构建用户交互时间线       |
| EM-08 | 语义搜索 | 按语义相似度搜索历史     |
| EM-09 | 混合搜索 | 结合语义和关键词搜索     |

**事件类型**: task_completed、preference_changed、important_info、milestone、decision、error、feedback

**非功能需求**: 搜索延迟 < 200ms

### 4.2 L2 画像记忆

**目的**: 存储用户事实、偏好和行为模式

**功能点**:

| ID    | 功能     | 说明                         |
| ----- | -------- | ---------------------------- |
| PM-01 | 事实管理 | CRUD 用户事实（分类+置信度） |
| PM-02 | 偏好管理 | 获取/更新/重置用户偏好       |
| PM-03 | 行为模式 | 检测、记录、应用行为模式     |
| PM-04 | 自动提取 | 从对话中提取用户事实         |
| PM-05 | 冲突处理 | 处理新旧信息冲突             |
| PM-06 | 敏感标记 | 标记和保护敏感信息           |
| PM-07 | 遗忘请求 | 处理用户的遗忘请求           |
| PM-08 | 模式确认 | 用户确认/否定推断的模式      |

**事实类别**: personal、work、hobby、skill、relationship、health、finance、other

**非功能需求**: 事实查询延迟 < 100ms

### 4.3 L3 知识记忆

**目的**: 管理文档、向量索引，支持语义检索

**功能点**:

| ID    | 功能     | 说明                         |
| ----- | -------- | ---------------------------- |
| KM-01 | 文档上传 | 支持 PDF/DOCX/XLSX/MD/TXT 等 |
| KM-02 | 文档解析 | 提取文档文本内容             |
| KM-03 | 文档分块 | 按语义切分文档               |
| KM-04 | 向量索引 | 生成嵌入并存储到向量数据库   |
| KM-05 | 向量搜索 | 语义相似度搜索               |
| KM-06 | 混合搜索 | 向量 + BM25 混合检索         |

**预留扩展** (@future):

| ID    | 功能     | 说明                         |
| ----- | -------- | ---------------------------- |
| KM-07 | 实体提取 | 从文档提取实体               |
| KM-08 | 关系提取 | 识别实体间关系               |
| KM-09 | 图谱查询 | 支持 Cypher 查询             |
| KM-10 | 社区检测 | GraphRAG 社区摘要            |
| KM-11 | 知识问答 | 基于图谱的问答（带来源引用） |

**非功能需求**: 向量搜索 < 300ms

## 7. 可插拔架构设计

### 7.1 设计原则

1. **接口优先**: 所有记忆类型定义统一接口，实现与接口分离
2. **依赖注入**: 通过工厂创建提供者实例，配置驱动的提供者选择
3. **独立部署**: 记忆系统可独立于主应用部署，通过 RPC/HTTP 提供服务
4. **零侵入集成**: 集成时不修改现有代码结构，支持渐进式迁移

### 7.2 提供者工厂

```typescript
class MemoryProviderFactory {
  private static providers: Map<string, ProviderConstructor> = new Map();

  static register(type: string, name: string, constructor: ProviderConstructor): void;
  static create<T extends IMemoryProvider>(type: MemoryType, config: ProviderConfig): T;
}

// MemoryType = "episodic" | "profile" | "knowledge"

// 注册示例
MemoryProviderFactory.register("episodic", "memory", MemoryEpisodicMemoryProvider);
MemoryProviderFactory.register("episodic", "postgres", PostgresEpisodicMemoryProvider);
MemoryProviderFactory.register("profile", "memory", MemoryProfileMemoryProvider);
MemoryProviderFactory.register("profile", "postgres", PostgresProfileMemoryProvider);
MemoryProviderFactory.register("knowledge", "simple", SimpleKnowledgeMemoryProvider);
```

### 7.3 配置系统

```yaml
# 开发环境配置（全部使用内存实现）
memory:
  episodic: { provider: memory }
  profile: { provider: memory }
  knowledge: { provider: simple }

# 生产环境配置
memory:
  episodic:
    provider: postgres
    options: { url: ${DATABASE_URL} }
  profile:
    provider: postgres
    options: { url: ${DATABASE_URL} }
  knowledge:
    provider: simple
    options: { dataDir: ./.memory/knowledge }
```
