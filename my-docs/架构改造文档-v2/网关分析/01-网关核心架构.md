## 1. 系统总览

Gateway 是 MtBot 的 **WebSocket 控制平面**，桥接消息频道、Agent 会话、客户端应用和工具系统。

```
┌───────────────────────────────────────────────────────────────────────┐
│  消息频道 (Telegram / Discord / Slack / WhatsApp / Signal / iMessage) │
│    ↕  HTTP Webhook / WebSocket / Long Poll                            │
├───────────────────────────────────────────────────────────────────────┤
│                     Gateway  ws://localhost:18789                      │
│                                                                       │
│  ┌──────────┐  ┌──────────┐  ┌───────────┐  ┌──────────────────────┐ │
│  │ 路由系统  │  │ 认证系统  │  │ 会话管理   │  │ 配置系统 (文件+DB)   │ │
│  └──────────┘  └──────────┘  └───────────┘  └──────────────────────┘ │
│  ┌──────────┐  ┌──────────┐  ┌───────────┐  ┌──────────────────────┐ │
│  │ Agent 引擎│  │ 工具系统  │  │ 记忆服务   │  │ 插件 / 钩子扩展      │ │
│  └──────────┘  └──────────┘  └───────────┘  └──────────────────────┘ │
├───────────────────────────────────────────────────────────────────────┤
│  客户端:  CLI  /  WebChat  /  macOS  /  Windows  /  iOS  /  Android   │
└───────────────────────────────────────────────────────────────────────┘
```

## 3. WebSocket 协议

### 3.1 帧格式（JSON-RPC 2.0 风格）

| 帧类型   | 方向            | 结构                                                     |
| -------- | --------------- | -------------------------------------------------------- |
| **请求** | 客户端 → 服务端 | `{ type: "request", id, method, params }`                |
| **响应** | 服务端 → 客户端 | `{ type: "response", id, ok, payload?, error? }`         |
| **事件** | 服务端 → 客户端 | `{ type: "event", event, payload, seq?, stateVersion? }` |

**帧类型定义** (`src/gateway/protocol/schema/frames.ts`):

```typescript
type RequestFrame = {
  type: "request";
  id: string; // 请求唯一 ID（用于匹配响应）
  method: string; // RPC 方法名，如 "chat.send"
  params?: Record<string, unknown>;
};

type ResponseFrame = {
  type: "response";
  id: string; // 对应请求的 ID
  ok: boolean; // 成功/失败
  payload?: unknown; // 成功时的数据
  error?: ErrorShape; // 失败时的错误信息
};

type EventFrame = {
  type: "event";
  event: string; // 事件名，如 "chat", "presence"
  payload: unknown; // 事件数据
  seq?: number; // 事件序列号
  stateVersion?: {
    // 状态版本（用于乐观更新）
    presence?: number;
    health?: number;
  };
};
```

### 3.2 连接生命周期

```
客户端发起连接
│  ws://gateway:18789/ws
│
├─ ① 服务端发送握手挑战
│     { type: "event", event: "connect.challenge", payload: { nonce, ts } }
│
├─ ② 客户端响应连接请求
│     { type: "request", method: "connect", params: { role, token, capabilities } }
│
├─ ③ 服务端认证验证
│     Token / 密码 / Tailscale / 设备令牌
│     → 成功：发送 ResponseFrame { ok: true }
│     → 失败：关闭连接
│
├─ ④ 握手超时管理
│     超时时间通过 getHandshakeTimeoutMs() 获取
│     超时未完成握手 → 自动关闭连接
│
├─ ⑤ 正式通信阶段
│     双向 Request / Response / Event
│
└─ ⑥ 断连处理
      更新节点注册表 → 广播 presence 事件 → 清理资源
```

## 5. 广播系统

**文件**: `src/gateway/server-broadcast.ts`

```typescript
broadcast(event, payload, opts?) → void
```

**特性**:

- 将事件发送给所有连接的客户端
- 权限过滤（基于作用域守卫）
- 可选速率限制（`dropIfSlow`）
- 序列号和状态版本跟踪
