# 技能客户端侧执行与用户自建技能设计方案

## 1. 核心原则

**Gateway 只执行系统内置技能（builtin），其余所有技能一律在客户端设备上执行。**

理由：

- **安全**：用户代码（Python/TS/Shell）不在服务器上运行，消除服务端代码注入风险
- **资源**：Gateway 不承担用户技能的计算负担，只做调度和元数据管理
- **隐私**：用户的本地文件操作在自己设备上完成，数据不经过服务器

### runMode 简化

| 模式         | 含义         | 执行位置                     |
| ------------ | ------------ | ---------------------------- |
| `server`     | 系统内置技能 | Gateway 服务端（仅 builtin） |
| `local`      | 所有其他技能 | 客户端设备                   |
| ~~`hybrid`~~ | ~~已废弃~~   | ~~不实现~~                   |

## 4. Gateway 侧变更：Skill Router

### 4.1 执行路由逻辑

在 `executor.ts` 中增加 `runMode` 路由：

```
executeSkill(skillId, params, context)
  ├─ 查找技能 (registry)
  ├─ 权限检查
  ├─ 路由:
  │   ├─ runMode === "server" && origin === "builtin"
  │   │   → 现有逻辑，Gateway 本地执行
  │   ├─ runMode === "server" && origin !== "builtin"
  │   │   → 拒绝：非内置技能不允许在 Gateway 执行
  │   └─ runMode === "local"
  │       → dispatchToNode()
  └─ 返回结果
```

### 4.2 dispatchToNode 流程

```typescript
async function dispatchToNode(
  skillRecord: SkillRecord,
  context: SkillExecutionContext,
): Promise<SkillExecutionResult> {
  // 1. 确定目标设备
  const targetNodeId = context.deviceId || (await selectBestNode(context.userId, skillRecord));

  if (!targetNodeId) {
    return { success: false, error: "NO_AVAILABLE_DEVICE" };
  }

  // 2. 检查设备是否在线
  const node = nodeRegistry.get(targetNodeId);
  if (!node) {
    return { success: false, error: "TARGET_DEVICE_OFFLINE" };
  }

  // 3. 通过 node.invoke 下发执行指令
  const result = await nodeRegistry.invoke({
    nodeId: targetNodeId,
    command: "skill.execute",
    params: {
      skillId: skillRecord.id,
      skillVersion: skillRecord.metadata.version,
      params: context.params,
      permissions: skillRecord.metadata.permissions,
      timeoutMs: 60_000,
    },
    timeoutMs: 65_000,
  });

  // 4. 转换结果
  return {
    success: result.ok,
    data: result.payload,
    error: result.error?.message,
  };
}
```

### 4.3 设备选择策略

```typescript
async function selectBestNode(userId: string, skillRecord: SkillRecord): Promise<string | null> {
  // 1. 获取用户所有在线设备
  const onlineNodes = nodeRegistry.getByUserId(userId);
  if (onlineNodes.length === 0) return null;

  // 2. 过滤：设备已安装该技能
  const withSkill = onlineNodes.filter((node) =>
    node.cachedSkills?.some((s) => s.skillId === skillRecord.id),
  );

  if (withSkill.length === 0) {
    // 没有设备安装了该技能 → 返回主设备（提示需要安装）
    return onlineNodes.find((n) => n.isPrimary)?.id || onlineNodes[0]?.id || null;
  }

  // 3. 优先级：主设备 > 最近活跃
  return withSkill.sort((a, b) => {
    if (a.isPrimary) return -1;
    if (b.isPrimary) return 1;
    return b.lastActivityAt - a.lastActivityAt;
  })[0].id;
}
```

```typescript
class TypeScriptRunner {
  /**
   * 在 Node.js 子进程中执行 TS 技能
   * - 通过环境变量传递参数
   * - stdout 收集 JSON 结果
   * - 内存限制 256MB，超时自动 kill

    const child = spawn("node", ["--max-old-space-size=256", entryPath], {
      cwd: skillDir,
      env: {
        ...sanitizedEnv,
        SKILL_PARAMS: JSON.stringify(context.params),

      timeout: context.timeoutMs,
    });
    // 收集 stdout/stderr，等待退出码
  }
}
```

```typescript
class PythonRunner {
  /**
   * 在 Python 子进程中执行 Python 技能
   * - 自动检测 python3/python
   * - 优先使用技能目录下的 .venv
   * - stdin/stdout JSON 协议通信
   */
  async run(entryPath: string, context: RunContext): Promise<SkillRunResult> {

      timeout: context.timeoutMs,
    });

  }
}
```

```typescript
class SkillSandbox {
  /**
   * 根据权限声明创建受限执行环境
   */
  createSandboxedEnv(permissions: SkillPermissions): SandboxEnv {
    return {
      // 环境变量白名单（移除 API key、token 等敏感变量）
      env: this.sanitizeEnv(process.env),

      // 文件系统限制
      allowedPaths: {
        read: [
          ...(permissions.fileSystem?.read || []),
          skillDir, // 自身目录始终可读
        ],
        write: [
          ...(permissions.fileSystem?.write || []),
          tempDir, // 临时目录始终可写
        ],
      },

      // 网络限制
      allowedDomains: permissions.network?.domains || [],

      // 进程限制
      allowedProcesses: permissions.process?.launch || [],

      // 资源限制
      maxMemoryMB: 256,
      maxCpuTimeMs: permissions.timeoutMs || 60_000,
    };
  }
}
```

## 6. 客户端手动安装技能文件

用户可以在 Windows 客户端 UI 中手动选择本地技能文件进行安装，不依赖商店或 Agent。

### 6.1 支持的安装来源

| 来源           | 说明                            | 格式                      |
| -------------- | ------------------------------- | ------------------------- |
| **本地目录**   | 选择包含 `skill.json` 的文件夹  | 目录路径                  |
| **压缩包**     | 选择 `.zip` / `.tar.gz` 技能包  | 解压后需含 `skill.json`   |
| **单文件脚本** | 选择 `.ts` / `.py` / `.sh` 文件 | 自动生成最小 `skill.json` |

### 6.2 安装流程

```

  │   ├─ "从文件夹安装" → Electron dialog.showOpenDialog({ properties: ['openDirectory'] })
```

### 7.2 新增 Agent 工具：skill_create

```typescript
// src/agents/tools/skill-create-tool.ts

function createSkillCreateTool(): AnyAgentTool {
  return {
    name: "skill_create",
    label: "Create Skill",
    description: `创建用户自定义技能。根据用户需求生成技能代码和清单，
打包并推送到用户设备执行。所有用户技能在客户端执行，不在 Gateway 运行。`,

    parameters: SkillCreateSchema,

    execute: async (_toolCallId, args) => {
      // args:
      // {
      //   name: string,
      //   description: string,
      //   language: "typescript" | "python" | "shell",
      //   code: string,
      //   triggers: SkillTrigger[],
      //   permissions: SkillPermissions,
      //   parameters: SkillParameter[],
      //   targetDeviceId?: string,       // 不指定则推送到主设备

      // 1. 构建 skill.json（runMode 强制为 "local"）
      const manifest = buildSkillManifest({
        ...args,
        runMode: "local", // 用户技能一律 local
      });

      // 2. 写入临时目录
      const skillDir = await writeSkillFiles(args.language, args.code, manifest);

      // 3. 编译 TypeScript（如需）
      if (args.language === "typescript") {
        await compileTypeScript(skillDir);
      }

      // 4. 校验
      const validation = await validateSkillPackage(skillDir);
      if (!validation.ok) {
        return errorResult(validation.errors);
      }

      // 5. Gateway 记录元数据（不加载代码到 Gateway 内存）
      await registerSkillMetadata(manifest, "user-created");

      // 6. 同步到数据库
      await syncSkillToDatabase(manifest, "local");

      // 7. 推送到目标设备
      const targetDevice = args.targetDeviceId || (await getPrimaryDeviceId(context.userId));
      if (targetDevice) {
        const pushResult = await pushSkillToDevice(targetDevice, skillDir);
        if (!pushResult.success) {
          return jsonResult({
            success: true,
            skillId: manifest.metadata.id,
            warning: `技能已创建但推送设备失败: ${pushResult.error}。请在设备端手动安装。`,
          });
        }
      }

      // 8. 清理临时目录
      await cleanup(skillDir);

      return jsonResult({
        success: true,
        skillId: manifest.metadata.id,
        message: `技能 "${args.name}" 已创建并推送到设备`,
      });
    },
  };
}
```

### 7.3 技能推送到设备

```typescript
// src/assistant/skills/push.ts

/**
 * 将技能包推送到目标设备
 *
 * 打包为 tar.gz → base64 编码 → node.invoke "skill.install" → 设备端解压安装
 */
async function pushSkillToDevice(
  nodeId: string,
  skillDir: string,
): Promise<{ success: boolean; error?: string }> {
  const manifest = await readManifest(skillDir);
  const packageBuffer = await packSkillDir(skillDir);

  const result = await nodeRegistry.invoke({
    nodeId,
    command: "skill.install",
    params: {
      skillId: manifest.metadata.id,
      version: manifest.metadata.version,
      packageBase64: packageBuffer.toString("base64"),
      packageHash: sha256(packageBuffer),
      manifest,
    },
    timeoutMs: 120_000, // 留足依赖安装时间
  });

  return { success: result.ok, error: result.error?.message };
}
```

### 7.4 设备端技能安装处理

```typescript
// apps/windows/src/main/skill-runner/installer.ts

class SkillInstaller {
  /**
   * 处理来自 Gateway 的 skill.install 命令
   */
  async handleInstall(params: {
    skillId: string;
    version: string;
    packageBase64: string;
    packageHash: string;
    manifest: SkillManifest;
  }): Promise<{ success: boolean; error?: string }> {
    // 1. 校验完整性
    const packageBuffer = Buffer.from(params.packageBase64, "base64");
    if (sha256(packageBuffer) !== params.packageHash) {
      return { success: false, error: "HASH_MISMATCH" };
    }

    // 2. 解压到本地存储
    const targetDir = path.join(SKILL_STORE_DIR, params.skillId, params.version);
    await extractArchive(packageBuffer, targetDir);

    // 3. 安装依赖
    const runtime = params.manifest.metadata.runtime;
    if (runtime === "typescript" && (await exists(path.join(targetDir, "package.json")))) {
      await execAsync("npm install --omit=dev", { cwd: targetDir });
    }
    if (runtime === "python" && (await exists(path.join(targetDir, "requirements.txt")))) {
      await this.setupPythonVenv(targetDir);
    }

    // 4. 更新本地索引
    await this.updateIndex(params.skillId, params.version, targetDir, params.manifest);

    return { success: true };
  }

  /**
   * 处理用户手动安装（从本地文件）
   */
  async handleLocalInstall(sourcePath: string): Promise<InstallResult> {
    // 1. 判断来源类型（目录 / 压缩包 / 单文件）
    const stat = await fs.stat(sourcePath);

    if (stat.isDirectory()) {
      return this.installFromDirectory(sourcePath);
    }

    const ext = path.extname(sourcePath).toLowerCase();
    if ([".zip", ".gz", ".tgz"].includes(ext)) {
      return this.installFromArchive(sourcePath);
    }

    if ([".ts", ".js", ".py", ".sh", ".ps1"].includes(ext)) {
      return this.installFromScript(sourcePath);
    }

    return { success: false, error: `不支持的文件类型: ${ext}` };
  }
}
```

## 10. 安全设计

### 10.1 分级策略

```
Level 0 (完全信任): Gateway builtin 技能
  → 无限制，直接在 Gateway 执行

Level 1 (已审核): 商店发布 + 管理员审核
  → 客户端执行，按权限声明限制
  → 首次需用户确认权限

Level 2 (用户自建): Agent 生成 / 手动安装
  → 客户端执行，严格沙箱
  → 首次执行强制 dryRun
  → 每次敏感操作需确认
```

### 10.2 用户确认流程

```
技能首次执行:
  → 弹出权限确认对话框:
    "技能 'auto-archive' 请求以下权限：
     - 读取: ~/Downloads/**
     - 写入: ~/Downloads/Archive/**

     [允许一次] [始终允许] [拒绝]"

后续执行:
  → "始终允许" → 静默执行
  → "允许一次" → 每次弹出确认
  → 权限变更时 → 重新确认
```

### 10.3 沙箱限制

| 限制项   | 默认值       | 说明                                |
| -------- | ------------ | ----------------------------------- |
| 内存上限 | 256 MB       | 超出则 kill 子进程                  |
| 执行超时 | 60 秒        | 可在 skill.json 中覆盖，上限 300 秒 |
| 文件访问 | 仅声明的路径 | 未声明路径的读写被拒绝              |
| 网络访问 | 仅声明的域名 | 未声明域名的请求被拦截              |
| 进程启动 | 仅声明的程序 | 未声明程序的 spawn 被拒绝           |
| 环境变量 | 白名单       | 移除 API key、token 等敏感变量      |
