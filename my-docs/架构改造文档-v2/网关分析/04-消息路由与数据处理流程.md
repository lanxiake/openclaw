### 1.1 路由解析

**返回结果**:

```typescript
type ResolvedAgentRoute = {
  agentId: string; // 匹配的 Agent ID
  channel: string; // 频道标识
  accountId: string; // 账户标识
  sessionKey: string; // 完整 session key
  mainSessionKey: string; // 主 session key
  matchedBy: string; // 匹配方式描述
};
```

### 1.2 匹配优先级

从高到低依次尝试匹配：

```
优先级 1 │ binding.peer       完全匹配 peer 的 kind + id
         │                    例: { peer: { kind: "dm", id: "123456" } }
─────────┤
优先级 2 │ binding.guild      Discord guild 专用匹配
         │                    例: { guildId: "987654" }
─────────┤
优先级 3 │ binding.team       MS Teams team 专用匹配
         │                    例: { teamId: "abcdef" }
─────────┤
优先级 4 │ binding.account    非通配符账户匹配
         │                    例: { channel: "telegram", accountId: "work" }
─────────┤
优先级 5 │ binding.channel    通配符账户 "*" 匹配
         │                    例: { channel: "telegram", accountId: "*" }
─────────┤
优先级 6 │ default            cfg.agents.default
```

### 1.3 Session Key 派生

**文件**: `src/routing/session-key.ts` (321 行)

#### DM Scope 模式

| DM Scope                   | Session Key 格式                        | 说明                 |
| -------------------------- | --------------------------------------- | -------------------- |
| `main`                     | `agent:main:main`                       | 所有 DM 共用一个会话 |
| `per-peer`                 | `agent:main:dm:123456`                  | 每个对等方独立       |
| `per-channel-peer`         | `agent:main:telegram:dm:123456`         | 频道+对等方          |
| `per-account-channel-peer` | `agent:main:telegram:default:dm:123456` | 完全隔离             |

#### 多租户格式

```
user:{userId}:agent:{agentId}:{mainKey}
```

**已有函数**:

```typescript
// 构建主会话 key
buildAgentMainSessionKey({ agentId }) → "agent:main:main"

// 构建对等会话 key（支持多种 dmScope）
buildAgentPeerSessionKey({ agentId, channel, accountId, peer, dmScope })

// 多租户 session key
buildUserAgentSessionKey({ userId, agentId, mainKey })

// ID 规范化（小写、去非法字符、长度限制）
normalizeAgentId(id) → string
normalizeAccountId(id) → string
```

## 2. 频道适配层

### 2.1 频道插件契约

**文件**: `src/channels/plugins/types.plugin.ts`

```typescript
type ChannelPlugin<ResolvedAccount = any> = {
  id: ChannelId; // "telegram" | "discord" | "slack" | ...
  meta: ChannelMeta; // 标签、文档链接、UI 元数据
  capabilities: ChannelCapabilities; // 支持的功能

  // ── 核心适配器 ──
  config: ChannelConfigAdapter; // 读/写配置
  setup?: ChannelSetupAdapter; // 初始化（token 输入等）
  pairing?: ChannelPairingAdapter; // QR/代码配对
  security?: ChannelSecurityAdapter; // 权限、allowlist
  auth?: ChannelAuthAdapter; // OAuth、token 轮换

  // ── 消息处理 ──
  outbound?: ChannelOutboundAdapter; // 发送消息
  groups?: ChannelGroupAdapter; // 群组策略
  mentions?: ChannelMentionAdapter; // @提及规范化
  directory?: ChannelDirectoryAdapter; // 联系人查询

  // ── 消息功能 ──
  actions?: ChannelMessageActionAdapter; // 按钮/卡片
  streaming?: ChannelStreamingAdapter; // 流式回复分块
  threading?: ChannelThreadingAdapter; // 线程/回复模式
  messaging?: ChannelMessagingAdapter; // 目标格式化

  // ── 运维 ──
  status?: ChannelStatusAdapter; // 健康检查
  heartbeat?: ChannelHeartbeatAdapter; // 保活
  gateway?: ChannelGatewayAdapter; // 自定义 RPC 方法

  // ── Agent 工具 ──
  agentTools?: ChannelAgentToolFactory | ChannelAgentTool[];
};
```

## 3. 端到端数据处理流程

### 3.1 完整流程图

```
┌──────────────────────────────────────────────────────────────────┐
│ ① 入站消息                                                       │
│                                                                   │
│   Telegram / Discord / Slack                                      │
│       ↓  HTTP Webhook / WebSocket                                 │
│   Channel Plugin (inbound handler)                                │
│       ↓                                                           │
│   Gateway 接收                                                    │
├──────────────────────────────────────────────────────────────────┤
│ ② 路由决策                                                       │
│                                                                   │
│   resolveAgentRoute({ channel, peer, account })                  │
│       ↓  返回 agentId + sessionKey                               │
│   triggerInternalHook("message:inbound", { msg, channel })       │
├──────────────────────────────────────────────────────────────────┤
│ ③ 消息理解                                                       │
│                                                                   │
│   applyMediaUnderstanding()        图片 / 音频 / 视频 → 文本描述 │
│   applyLinkUnderstanding()         URL → 摘要                    │
│   resolveCommandAuthorization()    allowlist 权限检查             │
├──────────────────────────────────────────────────────────────────┤
│ ④ Session 管理                                                   │
│                                                                   │
│   initSessionState()                                              │
│       ├─ 加载/创建 session                                       │
│       ├─ 加载历史消息                                             │
│       └─ 检查 context window                                     │
├──────────────────────────────────────────────────────────────────┤
│ ⑤ Agent 执行                                                     │
│                                                                   │
│   runAgentTurnWithFallback()                                     │
│       ↓                                                           │
│   runWithModelFallback()                                         │
│       ↓                                                           │
│   runEmbeddedPiAgent()                                           │
│       ├─ Auth Profile 选择                                       │
│       ├─ 模型调用 (streamSimple)                                  │
│       ├─ 工具调用（Sandbox 隔离）                                 │
│       ├─ 流式回复回调                                             │
│       └─ 错误恢复（Profile 轮转 / 模型回退 / Session 压缩）     │
├──────────────────────────────────────────────────────────────────┤
│ ⑥ 回复输出                                                       │
│                                                                   │
│   文本分块（根据频道限制）                                        │
│       ↓                                                           │
│   Channel Plugin outbound.sendMessage()                          │
│       ↓                                                           │
│   triggerInternalHook("message:outbound", { text, to, channel }) │
│       ↓                                                           │
│   Session 持久化                                                  │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 WebSocket RPC 调用流程

```
客户端发送 RequestFrame
│  { type: "request", id: "uuid", method: "chat.send", params: {...} }
│
├─ ① 帧格式验证
│     validateRequestFrame()
│
├─ ② 设备签名验证
│     DEVICE_SIGNATURE_SKEW_MS = 10 分钟
│     validateConnectParams()
│
├─ ③ 角色与权限检查
│     authorizeGatewayMethod()
│     → 检查 operator / node 角色
│     → 检查 admin / read / write / approvals 权限
│
├─ ④ 配额检查（多租户）
│     checkUserQuota()
│
├─ ⑤ 处理器路由
│     coreGatewayHandlers[method]     内置处理器
│     extraHandlers[method]           插件处理器
│
├─ ⑥ 执行处理器
│     handler(opts) → 业务逻辑
│
├─ ⑦ 发送响应
│     ResponseFrame { ok: true, payload }
│     或 ResponseFrame { ok: false, error }
│
└─ ⑧ 配额记录
      recordQuotaUsage()
```

### 3.3 事件推送流程

```
服务端发起事件
│
├─ broadcast(event, payload, opts)
│
├─ 权限过滤
│     → 按作用域守卫过滤连接
│     → 速率限制（dropIfSlow）
│
├─ 序列号管理
│     → 递增 seq
│     → 附加 stateVersion
│
└─ 发送到所有符合条件的客户端
      EventFrame { type: "event", event, payload, seq }
```

### 3.4 聊天流式数据流

```
用户发送消息 (chat.send)
│
├─ 创建 ChatAbortControllerEntry
│
├─ Agent 开始执行
│     ↓
│   onPartialReply() → 发出 "chat" 事件
│     { type: "event", event: "chat", payload: { delta, runId } }
│
├─ 工具调用
│     ↓
│   onToolResult() → 发出 "agent" 事件
│     { type: "event", event: "agent", payload: { tool, result } }
│
├─ 执行完成
│     ↓
│   发出最终 "chat" 事件
│     { payload: { done: true, fullText, runId } }
│
└─ 清理
      删除 ChatAbortControllerEntry
      持久化 session
```
