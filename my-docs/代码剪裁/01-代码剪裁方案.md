# MtBot 代码剪裁方案

> 版本: 1.0 | 创建日期: 2026-02-18 | 状态: 待评审

---

## 1. 背景与目标

### 1.1 产品定位

- **产品名称**：麦图助手（mtbot）
- **核心功能**：AI 驱动的个人电脑助手
- **当前支持平台**：Windows 客户端（P0）
- **后续支持平台**：macOS、iOS、Android（P1）
- **核心架构**：Gateway + App Server + 客户端

### 1.2 剪裁目标

- 移除与产品无关的代码，减少维护负担
- 保留核心功能和后续扩展所需的基础设施
- 保留微信/企业微信通道，支持后续多通道扩展

### 1.3 代码库现状

| 指标         | 数值        |
| ------------ | ----------- |
| 总代码行数   | ~113K LOC   |
| 总代码文件数 | ~1,765 文件 |
| 代码库大小   | ~1.15GB     |

## 4. 需进一步评估的模块

### 4.1 认证扩展

以下认证扩展在 `src/agents/` 中有硬编码引用，需要评估是否使用对应的 LLM 提供商：

| 扩展                                  | 用途                     | 评估建议                 |
| ------------------------------------- | ------------------------ | ------------------------ |
| `extensions/google-antigravity-auth/` | Google Cloud Code Assist | 如不使用可移除           |
| `extensions/google-gemini-cli-auth/`  | Gemini CLI OAuth         | 如不使用可移除           |
| `extensions/minimax-portal-auth/`     | MiniMax 门户 OAuth       | **建议保留**（中国 LLM） |
| `extensions/qwen-portal-auth/`        | 通义千问门户 OAuth       | **建议保留**（中国 LLM） |

### 4.2 记忆系统扩展

| 扩展                         | 用途             | 评估建议         |
| ---------------------------- | ---------------- | ---------------- |
| `extensions/memory-lancedb/` | LanceDB 长期记忆 | 生产环境建议保留 |

**记忆系统现状分析**：

| 方面          | 状态    | 说明                                |
| ------------- | ------- | ----------------------------------- |
| 多租户隔离    | ✅ 完成 | PostgreSQL user_memories 表完整实现 |
| 向量存储      | ✅ 完成 | pgvector 集成，支持 HNSW 索引       |
| 情景记忆 (L2) | ✅ 完成 | 持久化、可检索、类型丰富            |
| 档案记忆 (L3) | ⚠️ 部分 | 使用 users 表，缺乏专用 profile 表  |
| 知识图谱 (L4) | ❌ 缺失 | 未列入当前优先级                    |

**memory-core vs memory-lancedb 关系**：

- `memory-core`：文件系统缓存式，轻量级，适合本地开发（**必须保留**）
- `memory-lancedb`：持久化向量数据库，适合生产环境长期存储（**建议保留**）

### 4.3 src/daemon/ 模块

| 目录          | 文件数 | 说明         |
| ------------- | ------ | ------------ |
| `src/daemon/` | 30     | 守护进程管理 |

**评估建议**：需确认 Windows 客户端是否依赖此模块。如果 Electron 自管理进程，可考虑移除。

## 7. 执行注意事项

### 7.1 移除前检查

1. **依赖检查**：使用 `grep -r "from.*telegram" src/` 等命令检查 import 引用
2. **测试覆盖**：确保移除后所有测试仍能通过
3. **构建验证**：执行 `pnpm build` 确认构建成功

### 7.2 移除步骤

1. 创建专用分支 `feat/code-pruning`
2. 按优先级分批移除
3. 每批移除后执行完整测试
4. 代码审查后合并

### 7.3 回滚策略

- 保留移除前的 commit hash
- 如有问题可通过 `git revert` 回滚
